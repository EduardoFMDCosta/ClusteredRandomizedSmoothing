# Clustered Randomized Smoothing for Stochastic Prediction Functions

Reference implementation and reproducibility package for the NeurIPS submission
**"Clustered Randomized Smoothing for Stochastic Prediction Functions"** (ID: 34554).

The repository implements the clustered $\alpha$-smoothing predictor and
the associated robustness certificate, together with the scripts that 
regenerate every figure in the paper.

---

## Repository layout

```
src/randomized_smoothing/        Library code (smoother, clustering,
                                 regions, optimization, certificates).
experiments/
├── stochastic_functions.py      Wrappers around TrajFlow / UAV3D / GMM models
│                                that expose them as stochastic predictors.
├── paper/                       One script per paper figure
│                                (illustrations + TrajFlow experiments).
├── rl_benchmarks/               UAV3D PPO training and visualisation
│                                (bimodal policy + 3-D rollout figures).
├── TrajFlowExperiment/          Pre-trained TrajFlow weights and inputs.
├── uav_3d/                      Pre-trained UAV3D PPO checkpoint and
│                                training metrics.
└── data/
    ├── figures/                 Generated paper PDFs (this is where most
    │                            scripts in `experiments/paper/` write).
    ├── analysis/                Numeric results (JSON/CSV) backing the
    │                            TrajFlow plots and the appendix tables.
    └── fixed_random_index_order.json
                                 Persistent random ordering used to choose
                                 evaluation indices in TrajFlow experiments
                                 (kept under version control so that the
                                 plots are bit-identical across runs).
tests/                           Unit tests for the optimisation and
                                 clustering primitives.
pyproject.toml                   Project metadata + dependency declarations.
uv.lock                          Fully resolved dependency lock file.
Dockerfile                       Pinned environment for byte-reproducible runs.
```

## Installation

The project is managed with [uv](https://docs.astral.sh/uv/). Two options:

### 1. Native install with uv (recommended for development)

```bash
# install uv (https://docs.astral.sh/uv/getting-started/installation/)
curl -LsSf https://astral.sh/uv/install.sh | sh

# install the project (creates .venv/ and pulls every dependency from uv.lock)
uv sync --extra plots
```

`--extra plots` pulls `matplotlib` and `pyvista`, which are only needed when
regenerating figures (they are not required to use the library).

To run any command inside the resolved environment, prefix it with `uv run`,
or activate the venv with `source .venv/bin/activate`.

The figure scripts under [experiments/rl_benchmarks/](experiments/rl_benchmarks/)
import sibling helpers from [experiments/](experiments/) (e.g.
`stochastic_functions`), so add `experiments/` to `PYTHONPATH` when running
them natively:

```bash
export PYTHONPATH="$PWD/experiments"
```

The Docker image already sets this. Matplotlib's `text.usetex` is on, so a
working LaTeX install with `cm-super`, `dvipng`, and the `underscore` package
is required for native runs (the Docker image bundles all of them).

The PyVista 3-D scripts also need a headless OpenGL backend. The Docker image
installs `libosmesa6` + `libegl1` and exports `PYVISTA_OFF_SCREEN=true`, so
nothing else is required there. For native runs on a server with no display,
either install OSMesa (`apt install libosmesa6 libegl1 libgl1-mesa-dri`) and
set `PYVISTA_OFF_SCREEN=true`, or wrap the invocation with `xvfb-run`:

```bash
xvfb-run -a uv run python experiments/rl_benchmarks/visualize_uav3d_robustified_pyvista.py
```

### 2. Docker (recommended for reproducing paper artefacts)

A `Dockerfile` is provided that pins Python, uv, and every system library
needed by `cvxpy`, `POT`, and `pyvista`'s headless renderer.

```bash
docker build -t clustered-rs .

# run with the data directory mounted so generated figures land on the host
docker run --rm -it \
    -v "$PWD/experiments/data:/app/experiments/data" \
    -v "$PWD/experiments/uav_3d:/app/experiments/uav_3d" \
    clustered-rs
```

Inside the container, every `uv run …` command in the rest of this README
works as-is.

## Reproducing the paper figures

All paper figures are regenerated by running the scripts in
[experiments/paper/](experiments/paper/) and
[experiments/rl_benchmarks/](experiments/rl_benchmarks/). The default
arguments of every script match the values reported in the paper, so the
fastest way to reproduce all artefacts is to run each script with no flags.

Each script writes its outputs to a deterministic path under
[experiments/data/figures/](experiments/data/figures/) (TrajFlow / theory) or
[experiments/uav_3d/](experiments/uav_3d/) (UAV3D RL). Re-runs overwrite
existing files in place; if you want a clean rebuild, just delete the target
directory before running.

### Quickstart: regenerate everything

```bash
# theory + illustration figures
uv run python experiments/paper/bound_comparison.py
uv run python experiments/paper/compare_distributions.py
uv run python experiments/paper/generalized_voronoi_illustration.py
uv run python experiments/paper/quantization_illustration.py

# TrajFlow figures (data + plots)
uv run python experiments/paper/trajflow_examples.py
uv run python experiments/paper/trajflow_wasserstein.py --no-regenerate || \
    uv run python experiments/paper/trajflow_wasserstein.py
uv run python experiments/paper/trajflow_robustness.py --no-regenerate || \
    uv run python experiments/paper/trajflow_robustness.py

# UAV3D RL figures (use the supplied policy.pt checkpoint)
uv run python experiments/rl_benchmarks/visualize_bimodal_robustified.py
uv run python experiments/rl_benchmarks/visualize_bimodal_attacked.py
uv run python experiments/rl_benchmarks/visualize_uav3d_robustified_pyvista.py
uv run python experiments/rl_benchmarks/uav3d_wasserstein.py --plot || \
    uv run python experiments/rl_benchmarks/uav3d_wasserstein.py --ot-method emd
```

The `--no-regenerate` flag on the TrajFlow scripts re-uses the cached
JSON/CSV under `experiments/data/analysis/`. Drop the flag (or pass
`--regenerate`) to recompute the underlying data; this is the slow path and
typically takes minutes-to-hours depending on the chosen number of inputs.

### Re-training the UAV3D policy (optional)

The repository ships a pre-trained checkpoint at
[experiments/uav_3d/policy.pt](experiments/uav_3d/policy.pt) and the
corresponding training curves in
[experiments/uav_3d/training_metrics.json](experiments/uav_3d/training_metrics.json),
so the RL figures can be reproduced without retraining. To retrain from
scratch:

```bash
uv run python experiments/rl_benchmarks/train_rl.py
```

Defaults match the values reported in the paper. Training logs metrics to
`experiments/uav_3d/training_metrics.json` and overwrites `policy.pt` on
completion.
